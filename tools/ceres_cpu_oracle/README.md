# Ceres CPU semantics oracle

This harness calls upstream Ceres encoding and value-batch getters directly. It does not instantiate an evaluator, load a model, or establish neural parity. It targets upstream commit `64558176ad4933d3cd85b5604133d6576de921d2` through an unchanged `Ceres.Chess` project reference.

`Program.cs` reconstructs complete FEN/UCI histories before upstream repetition calculation and history truncation, requests Q-blunder inputs 0.03 explicitly, and exports all 8,768 square bytes per position. It feeds exact binary16 raw primary/secondary WDL logits into the public `PositionEvaluationBatch` constructor and exports the twelve FP16 W/D/L/V getters. Temperatures 0.55/1.5 and blend 0.4 name the parameterless-options profile being tested; they are not a claim about effective deployed settings. No Python formula substitutes for these getters.

`transport.py` reads the pinned 128-row bank only when executed. It verifies row identities, legal complete histories, saved byte shape and exact FP16 representability. Sixteen explicit fixtures cover both sides, castling, promotion, en passant and repeated histories longer than eight positions. The comparison retains every byte disagreement by square and feature, separately comparing stored bank bytes and the current Python encoder. Value deltas against a conventional float64 softmax mixture are diagnostics, not an upstream equivalence assumption.

The prepared plan and exact shell command live at `/home/josh/projects/chess/scratchpad/bt4_joint20/ceres_cpu_semantics_plan_v1/implementation_v1/`. `setup.py` installs the pinned SDK only under the fresh task root, fetches the exact upstream commit, verifies twelve relevant source blobs, and explicitly restores dependencies. The next stage builds with `--no-restore`; the final stage exports, invokes the built DLL, and compares once. All stages use the existing owned process-group helper. No global SDK, package cache, HOME change, inference fallback or automatic retry is used.

The shared budget is 3,600 seconds inclusive: at most 1,200 setup/restore, 1,200 build and 900 transport/oracle/readout seconds, with remaining time for cleanup. CPU 10,11 is reserved for this oracle; the arena uses CPU 2,3. Numeric and .NET worker settings are two, GPU visibility is empty, and no address-space limit is imposed on CoreCLR. Required available RAM is 48 GiB at startup and 32 GiB while running; free disk is 162 GiB at startup and 150 GiB while running, with an 8 GiB aggregate allocated-byte task cap. The 162 GiB requirement includes the task allowance plus 4 GiB for other writers. Package closure, first-build compatibility and runtime static initialization remain unqualified until actual execution. Failure is preserved without extension.

Preparation validation: Python AST, project XML, all sixteen fixture histories legal, Ruff and shell syntax passed. The C# project has not been compiled, the SDK has not been downloaded, and saved payloads have not been read during preparation.
