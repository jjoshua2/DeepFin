# Closed actor and capped on-policy cycle interfaces

These are software capabilities, not an experiment selection, collection
admission, or permission to use a protected role. Existing THREE, cancelled 5k,
HOLD, exposure and resource stops still apply. No seed, roster, target mixture,
learning dose, actor or budget is selected here.

`scripts.core_closed_once_actor` adds the explicit `closed_once_learner` actor
kind to `scripts.core_finite_collect`. It consumes a caller-pinned Root9/ind11
delivery pair and the actual original contract, stage, closed owner, family tag
and observed saved-state certificate. It accepts the genuine global-once or
policy-anchor-once family; it does not fabricate the old generation-bank
contract, command or genealogy. The collector keeps its real one-checkpoint
load/build, architecture, full494 state, exact immutable-file and served-state
checks. The new tag and typed state fingerprint are checked on that actual
loaded payload. Earlier collector branches retain their own requirements.
The recipe-independent data auditor explicitly joins the new actor kind,
lineage, original boundary and observed typed state fingerprint before emitting
an unpromoted generation candidate. The existing accepted-bank API still needs
the genuine separate Root/ind audit acceptance; collection status is not enough.

The trusted caller must authenticate the exact Root/ind source and delivery
references before binding them. A status string alone is not a trust root.
The bridge does not repeat a previous public virtual-population consumer call,
run a model qualification, perform an extra forward or select a new actor.

Collection outputs remain producer evidence until the existing independent
TRAIN audit and accepted-generation-bank interface have actually accepted them.
More frames are not independent games, and game IDs are not globally unique.
Natural board/opening duplicates do not become a semantic deduplication rule.

Tests cover both global and positive policy-anchor metadata, actual collector
validator dispatch and its single-load interception with an inert494-state CPU
fixture, tag/state refusal before constructor, and the actual raw/Zarr/FakeTB
data-audit-to-bank-API route. These use fictional trusted metadata and owned
synthetic tensors only; they are not production receipts or evidence of a real
collected generation. They remain unrun until an authorized test phase.
