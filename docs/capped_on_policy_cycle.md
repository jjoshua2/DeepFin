# Closed actor and capped on-policy cycle interfaces

These are software capabilities, not an experiment selection, collection
admission, or permission to use a protected role. Existing THREE, cancelled 5k,
HOLD, exposure and resource stops still apply. No seed, roster, target mixture,
learning dose, actor or budget is selected here.

`scripts.core_closed_once_actor` adds the explicit `closed_once_learner` actor
kind to `scripts.core_finite_collect`. It consumes a caller-pinned Root9/ind11
delivery pair and the actual original contract, stage, closed owner, family tag
and observed saved-state certificate. It accepts the genuine global-once or
policy-anchor-once family; it does not fabricate the old generation-bank
contract, command or genealogy. The collector keeps its real one-checkpoint
load/build, architecture, full494 state, exact immutable-file and served-state
checks. The new tag and typed state fingerprint are checked on that actual
loaded payload. Earlier collector branches retain their own requirements.
The recipe-independent data auditor explicitly joins the new actor kind,
lineage, original boundary and observed typed state fingerprint before emitting
an unpromoted generation candidate. The existing accepted-bank API still needs
the genuine separate Root/ind audit acceptance; collection status is not enough.

The trusted caller must authenticate the exact Root/ind source and delivery
references before binding them. A status string alone is not a trust root.
The bridge does not repeat a previous public virtual-population consumer call,
run a model qualification, perform an extra forward or select a new actor.

Collection outputs remain producer evidence until the existing independent
TRAIN audit and accepted-generation-bank interface have actually accepted them.
More frames are not independent games, and game IDs are not globally unique.
Natural board/opening duplicates do not become a semantic deduplication rule.

Tests cover both global and positive policy-anchor metadata, actual collector
validator dispatch and its single-load interception with an inert494-state CPU
fixture, tag/state refusal before constructor, and the actual raw/Zarr/FakeTB
data-audit-to-bank-API route. These use fictional trusted metadata and owned
synthetic tensors only; they are not production receipts or evidence of a real
collected generation. They remain unrun until an authorized test phase.

## Fresh-bank finite continuation

`scripts.core_capped_on_policy_cycle_proof` is the observed public entry. Its
CLI is `--contract PATH --contract-sha256 SHA --stage PATH --stage-sha256 SHA`.
It never launches an owner. The caller must bind a method and independently
reviewed current software/resource/source profile before any invocation.

The new contract schema is `core_capped_on_policy_cycle_v1`. One contract names
one cycle and one immutable compiled population containing exactly one actual
accepted TRAIN bank. It binds the bank's Root/ind refs, manifest/plan/origin and
membership identities, batch size, one derived `ceil(rows / batch_size)` update
count, independent shuffle seed/digest, ordinary runtime/flat-LR/target/anchor
recipe, finite read/decode/lineage-row bounds and a persistent quota path. The
stage schema is `core_capped_on_policy_cycle_stage_v1` with exact fields
`schema, contract_sha256, segment, cycle, population, parent, output`; `segment`
is 1 within each cycle. Source logical generation and cumulative optimizer step
are separate values. No invented consecutive generation roster is needed.

The separately pinned method must explicitly contain schema
`CORE_CAPPED_ON_POLICY_CYCLE_METHOD_V1`, `study_uuid`, `origin` and the exact
`cycle_recipe` returned by `recipe(contract)`. That check does not authenticate a
method issuer or grant execution authority. No real method values are selected
by this document or by the software defaults.

Two explicit starts are supported:

- `origin.family=model_only`, schema `CORE_CAPPED_CYCLE_MODEL_ONLY_ORIGIN_V1`,
  exact fields `schema, family, model, architecture, recorded_step`. The first
  cycle has `parent=null`. Existing `fresh_model` loads model weights only into a
  new Trainer: student step 0, empty optimizer state, fresh scheduler/zclip and
  declared seed. The producer's historical donor step (for A39, 680276) remains
  a provenance value, not the student's optimizer step. The ledger is created
  exclusively; an existing failed/sibling ledger cannot be silently reused.
- A genuine accepted `global_union` or `policy_anchor` delivery descriptor as
  `origin` and the same descriptor as first `parent`. This continues full state
  and all existing journal/ledger usage; it does not force the use of an
  unsuccessful candidate or discard the earlier fixed-population pass.

Every later cycle uses the exact adjacent `capped_cycle` delivery, the same
origin/learning-lineage UUID/quota path and maximum presentation cap. It restores
the actual model, optimizer moments/names, scheduler, cumulative step, zclip and
five RNG streams with the existing full-state bootstrap helper. The passive
observer compares the whole initial state fingerprint with the parent's final
fingerprint and checks RNG continuity. Constructor/teacher loading cannot stand
in for that restore. Target shares, frozen reference, runtime and flat-LR recipe
remain unchanged, including the remaining declared schedule horizon.
Before any row reservation, actual optimizer parameter names, type and every
non-tensor group control (including LR/decay), scheduler family/period/floor/base
LRs and noClip mode are compared with the fresh constructor under the selected
current source. Full-state bootstrap may not silently override this recipe.
The observed certificate records this actual profile as well as the complete
parent-to-child state fingerprint; no historical Trainer source pin is relabeled.

The new bank's actual producing actor checkpoint SHA and recorded step must equal
the selected parent's checkpoint and step. For a model-only first cycle these
are the immutable donor SHA and historical donor step. New collection UUIDs and
source generations remain their actual producing identities; they are not
renumbered to resemble old learner segments. The caller still has to select a
genuinely new, preplanned collection and its protected roles; this interface does
not infer scientific freshness merely from a different filename or timestamp.

Each cycle uses the existing uniform without-replacement replay adapter. The
actual final remainder is emitted once, never dropped or padded, with the same
actual-batch/requested-batch objective scaling and real adaptive optimizer/decay
step as the existing once family. The local permutation/cursor is distinct from
the cumulative ledger. Before decode/model construction, actual sealed prior
journals establish per-original `(generation, source_sha256, row_index)` counts.
Reservations append to the same locked write-ahead ledger and local journal and
fsync before mirroring/forward. Maximum total presentations is explicitly 1 or 2;
original and mirror share one reservation. No study-UUID or output-directory
change resets it. A failed tail is spent, taints the output, and refuses an older
checkpoint rather than wrapping, truncating or retrying.

This is a controlled learning-lineage cap, not a worldwide position-use registry.
A model-only restart is explicitly a new learning lineage, not a claim to resume
an older optimizer or erase older research exposure. Trusted admission must bind
the original producing identities and relevant prior controlled use. Naturally
identical boards/openings in independently produced stored rows remain distinct;
more frames/source assets are not independent games or an ESS estimate.

`scripts.core_capped_on_policy_cycle_proof.validate_closed_model_delivery(contract_ref, closed_binding)` is the explicit
new owned consumer. It checks the actual bounded sealed row journals (including
the cumulative cap and this cycle's exact order), manifest metadata, closed-owner
command and observed saved-state certificate. **Unlike the old global metadata
consumer it is not payload-free:** its caller must own the journal-read scope.
It performs no checkpoint/shard decode, model construction, draw or forward.
It returns a candidate model dictionary with the existing eight-field serving
shape, typed tensor-tree fingerprint, and new `core_capped_on_policy_cycle_v1`
tag; this is not a Root delivery or playing acceptance.

Future postclosure Root9/ind11 delivery statuses are explicitly
`ROOT_ACCEPTS_CLOSED_CAPPED_ON_POLICY_CYCLE_MODEL_DELIVERY_V1` and
`ACCEPT_CLOSED_CAPPED_ON_POLICY_CYCLE_MODEL_DELIVERY_NO_FINDINGS_V1`. Their exact
fields match the established Root9/ind11 surface. The closed actor bridge can
consume that genuine pair on a subsequent collection without repeating the
owned journal consumer. A future playing wrapper must explicitly bind the new
family/tag and actual deciding method; the current private U1/U2 named protocol
and driver whitelists are not silently expanded by this module. Existing arena
numerical kernels and typed-fingerprint primitives can be reused.

No existing learner/collector default, shared Trainer/loss, frozen runtime,
protected-role stop, actual ledger, native build, method, scope or owner changes
as a result of adding these files. Synthetic integration tests exercise fresh
model-only start, two real Tiny bank continuations, carried optimizer/RNG state,
both anchor fastpaths, actual tail row coverage, no-reset/actor-step/tampering
refusals and durable failure tails. They remain **unrun** pending hosted CI or an
explicitly selected software-validation owner; no real on-policy gain is claimed.

The proof module binds explicit typed delivery/payload callbacks from the actor
bridge into the shared cycle entry and owns the CLI/public delivery consumer.
This keeps the actor, entry and proof import graph acyclic without a dynamic
module registry, global monkeypatch, or ignored checker diagnostic.

The adjacent trust boundary is the genuinely accepted prior Root9/ind11 pair.
Actor transport reads only its current contract/stage/closed owner/proof and
compact model/tag aliases; it neither regenerates a virtual order nor recursively
reopens every older bank/delivery. The current owned consumer still validates
the new bank, exact order, cumulative actual journals and immediate full-state
handoff. Monotonic adjacent cycle counters prevent self-parenting. Per-row counts
stay in the owned journal/ledger fold, represented in metadata by bounded summary
and digest; prior model dictionaries and full prior permutations are not nested.
Current boundary/public delivery metadata must fit 4 MiB compact JSON. Hundreds
of cycles are supported within explicitly selected cumulative row/journal bounds;
these are not a grant for unlimited history reads or independent-game claims.
