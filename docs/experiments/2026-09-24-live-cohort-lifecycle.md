# Persistent cohort lifecycle (PR5d candidate)

## Preregistration — September 24, 2026

Base: #863 at bb1847d2d7f3c4e8b94e5dfb9f64bfc87e0c3390.
The reconstructed entire Git tree matches b6934d799a2c575388aeeb419645b9e1ab714ab1.
No merge/deployment, live jobs, trained model or GPU use. GitHub write actions are
not exposed in this session; publish an exact patch with reproducible evidence.

Hypothesis: the existing Bend async engine can safely service a bounded persistent
set of reusable root slots without reloading the model, accepting stale controls,
or applying a retired generation's output to its replacement.

Design: a separate opt-in live entrypoint, shared AsyncRun progress/worker/backend.
Sixteen occupied slots maximum, one pending lifecycle operation, process-monotonic
non-reused generations, at most 65,535 reserved generations. Validate new position
history before cancellation. Replacement/removal commits only at a no-pending-batch
barrier. Root controls require (slot,generation). A result is reported once only
after physical retirement; lifetime work includes all reported generations.
Normal fixed-cohort and UCI entrypoints remain unchanged.

Controls: actual compiled Bend owner and inherited worker with deterministic
row-independent callback, explicit held callback, existing cohort serial reference,
malformed/replayed controls, full-history parsing, repeated slot reuse, queued
replace abandoned on stop/quit, EOF drain, capacity and generation exhaustion.
Normal and UBSan native execution; no generated-source/compiler patching.

Budget: one bounded local source generation, single compiler process, CPU only;
focused native tests and optional local fixture only where the installed runtime
can actually execute it. No network model download or training. Record unavailable
locked dependencies, full-compile/resource failures and actual model limits.
No performance/strength claim, tolerance change or substitution of component
checks for composition evidence. Self-review only unless independently reviewed.

### Scope and outstanding reconciliation

The candidate adds a separate entrypoint and leaves existing runtime paths intact.
A sixteen-slot persistent owner, generation-tagged controls, validation-before-
cancellation, drain-before-replacement and lifetime accounting are implemented
in source. These claims describe the draft, not observed whole-runner behavior.

The completed registry tests do not prove the wrapper's physical-drain ordering.
The Python tests do not prove that generated Bend emits those records correctly.
Successful type checking does not establish ABI composition or absence of runtime
errors. No independent reviewer was available; this is self-review only.

The newer parallel #866/#870/#874 stack changes queue representation, completion
waiting and arena capacity. This patch remains pinned to #863 and does not
incorporate or overwrite those changes. Reconcile those interfaces before moving
this entrypoint onto that stack; do not label it compatible merely because new
files apply cleanly. The fixed 4,096-node arena in this candidate is a property of
its old base, not a claim that the separate arena PR remains unfinished.

Even after native qualification, this is a live-root lifecycle interface, not
persistent self-play generation. The external caller still supplies positions and
moves; no training records, automatic game progression, adaptive service-time
selection, extra execution slots or GPU qualification are delivered.
