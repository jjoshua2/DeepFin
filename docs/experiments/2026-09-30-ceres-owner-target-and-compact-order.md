# Ceres generating-owner target reconstruction and compact-order correction

The mixed-source fair route can select Ceres for a row generated by Ceres. The
completed source game already retains that row's compact legal policy logits
and two value heads. `ceres_owner_target.py` reconstructs the selected Ceres
policy (temperature 0.5) and calibrated WDL (0.6 at temperature 0.55 plus 0.4
at temperature 1.5) from those heads without another teacher call. It checks
the pinned fair-route UID, source archive/model SHA, student input digest,
stored-feed SHA, history stack, legal context, and teacher query. The public
source entrypoint verifies one whole game once before reconstructing all of
its selected rows. Strict Syzygy games still require the owned rule50-aware
six-man WDL/DTZ handle. The source manifest and schedule root ID must come
from a separately authenticated route/index; the feed pin must come from the
terminal-bound physical-call ledger. A game archive alone cannot prove those
external bindings. In the one-row smoke below, the feed pin comes from the
saved row, so that smoke establishes reconstruction correctness only.

On the frozen 58,820-row bridge, 15,761 of 31,702 Ceres-source rows were
routed to Ceres. That count is an opportunity bound, **not** a saved-call or
throughput result: the code here does not integrate with the production label
writer, and source-versus-label numerical profiles still need a corrected
full-bank test. The saved-game reader's ZIP member cap rose from 64 to 512 so
it can open legitimate chunked source shards (the tested run11 shard has 118
members). Its 64 MiB archive and 8 MiB metadata caps remain in force.

The first real overlap exposed a separate problem in the **zero-credit full58k
cost diagnostic target output**. Run11 Ceres natural game 546, ply 116 is
selected for Ceres as bridge row 2. Its staged student input and Ceres feed
bytes match the saved source. All 11 saved legal logits equal the selected S1
raw head at the same Leela slots; both value heads agree byte for byte. Yet
the diagnostic selected policy differs from a compact-sorted reconstruction
by policy TV 0.1737060546875, while its WDL bytes agree. The old target
builder paired board-order Ceres Leela slots with ascending compact slots.
Its own readback repeated that pairing, so exact target-byte readback did not
test the intended move-to-logit association. A source-only corrected row
binder now keeps the board-order independent map check and supplies a
compact-sorted Ceres slot vector. The one-row regression shows the corrected
policy equals direct compact-sorted legal-logit softmax; it has not generated
replacement full-bank targets or changed the frozen diagnostic.

The historical trained E target builder uses `logits[np.nonzero(legal)]` on
compact-sorted legal slots, and the tracked Selected-E cost kernel gathers
with `np.flatnonzero(legal)`. Those inspected code paths do not contain this
board-order pairing error. This finding does not by itself establish the
quality of any trained cohort. The diagnostic's call/core timing remains a
timing measurement; its saved Ceres policy targets are unsuitable as an
intended-label reference until regenerated and independently checked.
