Suggested first implementation slice, after the shared helper's independent review: update only future `bt4_outcome.py` and in-memory `bt4_root_policy_stepper.py` on a new isolated branch, stack the approved strict helper, and require an explicit `rule50_match` mode plus strict tablebase handle for new match-correct bootstrap games. The old theoretical path remains named and unchanged for historical compatibility. Fake-tablebase tests should cover WDL ±1, ±2 at clock zero and positive/boundary clocks, both colors, natural claim first, WDL/DTZ missing and contradiction, all-game row discard with counters, no inference at terminal root, no mutation of native teacher arrays, and mode provenance in completed records. A follow-up SF-rooted schema/resume/engine change needs its own review because this generator produces persistent raw rows at scale. No GPU or real game run belongs in either code-review slice.

Measurement/acceptance before any new bootstrap corpus: fixed production 3–5+6 directories with WDL+DTZ capacity, one bounded CPU fake source-game test, a few real six-man probes only after resource authorization, explicit counts of natural/Syzygy/clock-ambiguous/missing/cap outcomes, zero <=6 banked rows, and paired physical-row/raw-teacher identity checks. A position-per-second claim requires a separate bounded real generation pilot with saved accepted rows and elapsed time; no such rate is inferred here.
