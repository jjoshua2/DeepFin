# Literal-UID source cursor and paired segment diagnostic

**CPU-only synthetic prototype, 2026-09-30. Zero archive, target, trainer, external-drive throughput, GPU, and 500M-row restart credit.** The [checkpointed sort](2026-09-30-tri-source-checkpointed-sort-foundation.md) used a synthetic source label as the second UID field. The qualified replay UID is instead `(source_manifest_sha, namespace, root_id, game_id, ply)`. Rewriting that UID would change the frozen teacher route, winner rank, and target join. In the frozen grouped adapter, the selected BT4 root has a 16-move UCI prefix, so its first emitted UID ply is 16; Ceres source rows start at 0 in that adapter. This successor binds the per-game UID ply start to the exact root prefix for BT4 and preserves all five literal fields. Each `(manifest, namespace)` pair maps to a pinned BT4, Ceres, or SF source label. Ceres and SF callbacks are not yet integrated; their actual row indices must be proven separately.

Three versioned diagnostic modules connect a whole-game reader interface to [paired-wave storage](../../chess_anti_engine/source/checkpointed_wave_v2.py), [100-byte metadata](../../chess_anti_engine/source/checkpointed_candidate_v2.py), and [a sealed cursor and bounded sort input](../../chess_anti_engine/source/checkpointed_cursor_v2.py). The reader callback takes an authenticated archive snapshot and returns complete replay rows plus the actual checked per-game source proof. It verifies the proof hash, strict receipt, terminal replay fact, and Syzygy inventory before attaching the proof identity to rows. A future real-source operator must supply the pinned adapter locator as `GameLocator.actual`, including its root UCI prefix, so the reader can check it against the cursor roster. This is an interface: the frozen BT4 `replay_one` callback and NPZ archive were **not** bound or read in this test. Ceres shard grouping and SF selected-game streaming remain separate integrations.

Each source segment holds at most 8,192 rows in 512-row Zstd frames. A cursor receipt records its exact source interval, including a whole-game hash when the boundary falls inside a game, and chains to the previous cursor receipt and paired-wave seal. On a midgame restart, the reader replays that whole bounded game and checks its hash before skipping the sealed prefix. A segment with a sealed wave but no cursor is reconstructed from source; if its comparison is already sealed, reconstruction consumes and compares the source rows with the authenticated wave instead of skipping them. The second wave compares ordered native bytes, UID, context, outcome, source proof, and provenance before metadata or sort input is admitted. Candidate readback rederives exact records and local tables from paired data; sort-run readback compares all at-most-2,048 entries with those candidates. A direct wave-2 call also requires every segment's roster-derived row count and the final cursor at the end of all games.

The synthetic fixture uses 8,195 **32-byte** rows from games of at most 256 rows: `31×256 + 255 + 2 + 1 + 1`. Its BT4-like UIDs begin at the 16-move root prefix. The 8,192-row seal lands inside the two-row game, followed by two more games. It sends actual `SIGKILL` after the first wave seal and, in a new process, after the comparison seal but before its cursor. A third process resumes, preserving both sealed receipt hashes and modification times; a no-op keeps the cursor receipt stable. Tests also refuse changed archive bytes, a false source-proof digest, native bytes changed between waves or after the comparison-before-cursor crash, source namespace or prefix/ply swaps, an actual adapter root-prefix mismatch, an old v2 cursor claim, exact duplicate source games, coordinated false candidate outcomes, a valid-but-false sort run, and a structurally valid two-row final segment against a four-row pinned roster. Reused numeric game IDs under different root IDs are allowed at this cursor boundary; a downstream pack still needs an explicit game-key policy.

The revised six cursor tests pass under Python 3.10; the unchanged 13 sort tests passed in the earlier combined 19-test run. Whole-repository Ruff and Vulture pass after the cursor revision. The whole-repository Basedpyright gate is not clean in this checkout: under the same declared Python 3.10 dependency overlay, base and candidate both report 439 errors and 7 warnings, with zero differences after normalizing relative file, line, column, rule, message, and multiplicity. The unqualified lint environment lacks several installed dependencies and produces misleading additional import diagnostics; it was not used for the baseline comparison. The [portable evidence](evidence/2026-09-30-tri-source-literal-uid-cursor.json) pins the source and results.

This bounded fixture does not establish a production source cursor or a 500M-row no-op cost. The diagnostic roster is held in memory, candidate verification re-decompresses a whole segment, and the callback code pin must be checked by a future actual-archive operator. The current cursor requires consecutive `ply_start + row_index` UIDs; filtered or noncontiguous SF positions are outside its protocol. Cooperative segment wall/RSS limits cannot preempt blocked source reads; an owned subprocess with an external at-most-600-second kill/reap watchdog, exact archive/game byte caps, and a separately reviewed source lease are required before any real read. No live producer or trainer path changed.


## October 1 hosted-test isolation correction

The historical focused run above did not establish success inside the complete Python 3.13 CPU suite. Hosted run 36790358198 exposed five `segment RSS cap` failures and one crash witness exiting before its expected SIGKILL. The store's guard intentionally measures absolute process-lifetime peak RSS, including earlier unrelated allocations. Running these fixtures in the heavyweight shared pytest process violates their owned-unit resource assumption. On Linux, exec also accounts the replaced address space's high-water RSS, so a direct child is not by itself a clean resource-accounting boundary.

The six existing behavioral fixtures now run as owned CPU units launched by a lightweight supervisor process. Both supervisor and case retain external deadlines and address-space caps, while every case keeps the unchanged 1-GiB absolute segment RSS default. Crash failures include their child logs. A deterministic budget regression checks exact-cap acceptance and repeated refusal above that cap; it does not replace real resource checks in the isolated fixtures. The source resource guard and production modules are unchanged. Current hosted CI is tracked on the pull request; no new archive, throughput, or 500M-row qualification follows from test isolation.
