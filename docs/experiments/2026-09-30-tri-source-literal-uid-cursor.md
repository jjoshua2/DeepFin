# Literal-UID source cursor and paired segment diagnostic

**CPU-only synthetic prototype, 2026-09-30. Zero archive, target, trainer, external-drive throughput, GPU, and 500M-row restart credit.** The [checkpointed sort](2026-09-30-tri-source-checkpointed-sort-foundation.md) used a synthetic source label as the second UID field. The qualified replay UID is instead `(source_manifest_sha, namespace, root_id, game_id, ply)`. Rewriting that UID would change the frozen teacher route, winner rank, and target join. This successor keeps the literal five fields and binds each exact `(manifest, namespace)` pair to its BT4, Ceres, or SF source label in a pinned roster.

Three versioned diagnostic modules connect a whole-game reader interface to [paired-wave storage](../../chess_anti_engine/source/checkpointed_wave_v2.py), [100-byte metadata](../../chess_anti_engine/source/checkpointed_candidate_v2.py), and [a sealed cursor and bounded sort input](../../chess_anti_engine/source/checkpointed_cursor_v2.py). The reader callback takes an authenticated archive snapshot and returns complete replay rows plus the actual checked per-game source proof. It verifies the proof hash, strict receipt, terminal replay fact, and Syzygy inventory before attaching the proof identity to rows. This is an interface: the frozen BT4 `replay_one` callback and NPZ archive were **not** bound or read in this test. Ceres shard grouping and SF selected-game streaming remain separate integrations.

Each source segment holds at most 8,192 rows in 512-row Zstd frames. A cursor receipt records its exact source interval, including a whole-game hash when the boundary falls inside a game, and chains to the previous cursor receipt and paired-wave seal. On a midgame restart, the reader replays that whole bounded game and checks its hash before skipping the sealed prefix. A segment with a sealed wave but no cursor is reconstructed from source; if its comparison is already sealed, reconstruction consumes and compares the source rows with the authenticated wave instead of skipping them. The second wave compares ordered native bytes, UID, context, outcome, source proof, and provenance before metadata or sort input is admitted. Candidate readback rederives exact records and local tables from paired data; sort-run readback compares all at-most-2,048 entries with those candidates. A direct wave-2 call also requires every segment's roster-derived row count and the final cursor at the end of all games.

The synthetic fixture uses 8,195 **32-byte** rows from games of at most 256 rows: `31×256 + 255 + 2 + 1 + 1`. The 8,192-row seal lands inside the two-row game, followed by two more games. It sends actual `SIGKILL` after the first wave seal and, in a new process, after the comparison seal but before its cursor. A third process resumes, preserving both sealed receipt hashes and modification times; a no-op keeps the cursor receipt stable. Tests also refuse changed archive bytes, a false source-proof digest, native bytes changed between waves or after the comparison-before-cursor crash, source namespace swaps, exact duplicate source games, coordinated false candidate outcomes, a valid-but-false sort run, and a structurally valid two-row final segment against a four-row pinned roster. Reused numeric game IDs under different root IDs are allowed at this cursor boundary; a downstream pack still needs an explicit game-key policy.

All six new cursor tests and 13 existing sort tests pass under Python 3.10. Whole-repository Ruff and Vulture pass. The whole-repository Basedpyright gate is not clean in this checkout: under the same declared Python 3.10 dependency overlay, base and candidate both report 439 errors and 7 warnings, with zero differences after normalizing relative file, line, column, rule, message, and multiplicity. The unqualified lint environment lacks several installed dependencies and produces misleading additional import diagnostics; it was not used for the baseline comparison. The [portable evidence](evidence/2026-09-30-tri-source-literal-uid-cursor.json) pins the source and results.

This bounded fixture does not establish a production source cursor or a 500M-row no-op cost. The diagnostic roster is held in memory, candidate verification re-decompresses a whole segment, and the callback code pin must be checked by a future actual-archive operator. Cooperative segment wall/RSS limits cannot preempt blocked source reads; an owned subprocess with an external at-most-600-second kill/reap watchdog, exact archive/game byte caps, and a separately reviewed source lease are required before any real read. No live producer or trainer path changed.
