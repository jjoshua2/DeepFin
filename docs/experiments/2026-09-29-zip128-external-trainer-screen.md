# Same-ZIP external trainer screen: 128 shards

**Readout, 2026-09-29.** A one-pair actual-trainer screen passed its precommitted short-path rule: the external-ZIP arm processed **2,081.983 measured rows/s**, versus **2,089.711 rows/s** from a local copy of the same ZIP bytes. The external/local ratio was **0.996302**, above the **0.95 pass threshold**. The 128-shard working set, prior staging and cache state make this a short-path result. It does not establish cold first-read throughput, a 500M-epoch rate, corpus admission or training strength.

## Frozen comparison and decision

The question was whether reading unchanged packed ZIP shards from external storage materially slows the actual trainer relative to reading those same bytes locally. A source-only random draw fixed **external first, local second** before staging. The comparison used 128 full shards covering 17 source cohorts and 1,048,576 rows. Each serial arm ran the same initial model, configuration, seed, batch-512 sampler and loader for one 2,048-update epoch. There was no simultaneous GPU arm or host-batch overlap. Independent CPU schedule proofs bound all 2,048 ordered row/game/ply batches, and the physical readback required matching raw and prepared tensor identities through training, exact source/local ZIP hashes before and after, finite losses and complete owned-process cleanup.

The primary rate was `sum(train_samples_seen) / sum(train_time_s)` over windows 3–24, excluding the first two completed windows in both arms. This retained **958,464 measured rows per arm**. The precommitted external/local rule was **<0.90 reject**, **0.90–<0.95 inconclusive** with a separately reviewed reverse-order repeat, and **≥0.95 pass this short-path screen**, provided all integrity, resource and readback gates passed. The screen offered no statistical confidence interval: its windows share one process, one model and one ordered run, so treating them as independent trials would overstate precision.

The parent published a physical PASS index after a 2,387.032-second wall interval from first admitted operation through terminal handling. An independent postrun checker then verified the issued authority and receipt chain, phase order, ZIP identities, trainer observations, batch parity, rate arithmetic, free canonical lock and absence of owned workers. Its result was `PASS_RUN12_INDEPENDENT_POSTRUN_AUDIT`; the benchmark screen was `PASS_SHORT_SAMEZIP_PATH` with **zero source, target, owner, corpus and 500M capacity credit**.

An optional bounded full-byte reread covered all **128 source plus 128 local ZIPs**, reading **1,429,957,770 logical bytes**. It passed its own integrity check but is explicitly **nonauthoritative** for the rate or terminal verdict. The core independent postrun audit is the deciding readback.

## Interpretation and evidence

This pair shows that the selected external path kept up with the local copy for this bounded, cache-affected actual-trainer workload. It does not isolate cold disk throughput: staging and preflight read source bytes before training, both arms used the same host caches, and the external arm ran first. The local copy also differs from an uncompressed local corpus. A 500M mixed-source pack can have different shard sizes, cache residence, target schema, first-read behavior and epoch order. Extrapolating `500,000,000 / 2,081.983 / 86,400 ≈ 2.780` ideal days for one epoch is an **optimistic cache-served sensitivity only**, not a measured production forecast. This receipt does not authenticate the older 1,281.357-row/s reference or the labeling and source-rate inputs used in cross-stage capacity scenarios. Consequently, it does not establish a 48.700-day pipeline floor or any other end-to-end completion estimate; those calculations require their own pinned producing receipts, admission yields and explicit overlap assumptions.
