# Per-root asynchronous cohort deadlines

## Preregistration — September 23, 2026

PR5c on #862 at `57bb9636e3e6fcfb6832bb2cd494279bacae4d38`.
No merge, deployment, live training, GPU use or production configuration changes.
The feature is an opt-in CPU cohort control, not dynamic root admission or a
complete adaptive/self-play scheduler. Synchronous behavior stays unchanged.

Hypothesis: per-root deadlines can stop admissions and suppress expired results
without cancelling unaffected roots, losing prior accepted work, or refunding
physical inference already admitted. Timers continue during pending callbacks,
partial/buffered commands and control EOF. No performance or Elo hypothesis.

Contract: `deadline ROOT MS` sets a relative timeout measured from command
processing, not process launch; MS is 0..3,600,000. Existing deadlines can only
shorten. Completed/stopped/expired roots cannot be revived. Deadline checks occur
before gathering, after gathering/row compaction, and before each result's
normalization/backup. Individual encoding/normalization/backup/output operations
remain synchronous; this is not a hard-real-time guarantee. Final cohort reports
still follow physical drain. Expired dispatched rows remain charged and wasted.

Acceptance: inherited no-deadline synchronous/async serial-reference checks pass;
explicitly held evaluator tests prove selective expiry before release, queued-root
zero dispatch, retention of prior accepted trees, EOF/backlog timer progress and
cancelled-output failure detection. Preadmission compaction must preserve every
surviving input value and row/ticket identity. Malformed/extension/reactivation
commands and contradictory v2 deadline reports must reject. Deadline-free legacy
report schemas remain readable; new timing/expiry fields are explicit, not inferred.
Use exact pinned compiler and inherited numerical tolerances, without weakening
oracles. Real-model no-deadline parity is a separate gate from deterministic
cancellation/expiry injection; do not conflate the two.

Budget: bounded hosted fresh C generation, normal/UBSan deterministic checks,
cheap Python regressions and two-thread CPU model validation. Reuse the saved
untrained 5,043,005-parameter CPU fixture and singleton package; at most one
batch-four export from identical checkpoint/encoding. No training, game matches,
real GPU, model architecture or new permanent heavy CI step. Retain compact
source/build/test identities and reports; no private model or raw neural traces.

Recovery: preserve failed reports, fix only the relevant layer, and requalify
changed source. Full local generation exceeded its 80-second bound after type
checking; that is not successful code generation. Hosted compilation is required.
Publish a separate reviewable branch only after explicit qualification. Independent
review is unavailable; all author checks must be labeled self-review, not proof.

### Deadline behavior demonstrated

In the six-root selective-expiry test, root 1 expires while already in the first
four-row forward, and root 6 expires before dispatch. Root 5 alone needs the second
call. The final result is **five executed rows: four accepted and one wasted**, plus
three padding rows. Unaffected roots 2-5 have bit-identical trees to the uncancelled
control. The expired queued root consumes zero admitted rows. A second test retains
root 1's previously accepted tree when its next row expires: eight executed rows,
seven accepted and one wasted. No computation reservation is refunded.

Other cases prove timer progress after stdin EOF and across 200 buffered readiness
commands, preserve a manual cancellation's reason, and expire a root before its
first gather with zero forwards. The backlog test explicitly suspends the process
past an installed deadline, then requires the notice before the backlog ends; this
is a functional control, not a deployment latency distribution. Eight malformed
command forms, deadline extension, revival and already-completed-root changes are
rejected. Failed/nonfinite callback output still rejects the run when its own row
has expired, without a successful summary or first-batch neural reply.

These tests link the actual generated Bend coordinator and native worker to the
existing callback held by test-only pipes. The pipes/callback are absent from the
model product. Deadlines are not mocked by a Python search loop. The separate
compiled timer/compaction probe covers immediate expiry, sticky expiry, inactive
roots, root 16 and a timestamp above U32. It checks all sixteen four-row removal
masks at each of the two input widths: every surviving input value, destination
row, original ticket identity, halted-root state and unused input-buffer tail.
This is not an exhaustive test of all 16-root masks or all clock interleavings.

### Ownership, scope and limitations

Bend retains every root, timer, input-row/ticket mapping and search update. The
existing native worker and model bridge are unchanged. `deadline ROOT MS` begins
when its command is processed, not at launch/caller write; zero is immediate, an
existing absolute due time may only shorten, and inactive roots cannot revive.
Checks occur before gather, after gather/compaction and before each returned
neural row begins normalization/backup. Expired preadmission rows are removed in
stable order; admitted work must drain and is accounted as wasted, never accepted.
All real raw outputs, including expired rows, still pass the whole-batch guard.

These are cooperative scheduling boundaries, not preemption. Individual encoding,
normalization/backup, diagnostics or output operations can cross a deadline. A
wedged callback is not killed. Final reports still wait for physical drain; this
is not an early UCI decision or a hard stop-latency guarantee. Async reports use
`deepfin.multi-root-async-work.v2`, while the synchronous schema stays unchanged.
The final clock includes setup, first inference, control and drain without excluded
warmup; phase/queue/GPU timings remain unavailable, not fabricated.

Live root admission/replacement, persistent self-play, service-time-driven dispatch,
multiple slots and actual trained-5090 qualification remain separate. Root arenas
are still 4,096 nodes; same-tree concurrency and production Gumbel parity are
unchanged. No normal UCI, production configuration or running job was modified.
