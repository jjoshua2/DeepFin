# Paired-pack auditor: exit-aware supervised wait

The integrated independent D-lite paired-pack auditor samples a running child every five seconds. Its previous `time.sleep(5)` also delayed recognition of a child that had already exited. The source successor changes only that sleep to `Popen.wait(timeout=5)` with `TimeoutExpired` returning to the existing loop. The next iteration still samples and fsyncs resources, checks the exit code and all wall/RSS/memory/physical-I/O/output/disk gates, verifies the unit result, and publishes its resource receipt. The existing process-group cleanup and pinned exec guard remain unchanged.

The auditor has two supervised units for each of 384 shards, plus label-index and final readback. If all 770 units finished just after a sample, the eliminated idle tail could total at most 3,850 seconds; actual savings depend on when each child exits and have **not** been measured on a real audit. Live-child resource sampling still occurs at most five seconds apart. This change does not alter dataset, labels, pack arrays, scientific checks, or admission criteria.

`tests/test_sf_dlite_auditor_exit_wait.py` uses real short-lived CPU children and the unchanged owned-child exec guard with synthetic host I/O counters and a temporary output root. It verifies prompt success plus terminal resource acceptance, nonzero exit with no resource credit, and a one-second deadline with no surviving child or resource credit. The isolated CPU source packet also exercised a child running beyond one sample interval, a synthetic resource refusal, and owner-death cleanup. No archive, production physical-I/O lease, engine, or GPU was used. This is a source/test candidate for review; production audit throughput and full-pack qualification remain unmeasured.
