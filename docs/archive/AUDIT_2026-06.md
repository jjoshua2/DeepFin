# Search + Training Correctness Audit — 2026-06

Scope: a correctness + Elo-efficiency pass over the search (Gumbel MCTS, both
the Python reference and the C fast path) and training (losses, targets,
optimizer, LR schedule, replay sampling, selfplay target generation)
subsystems.

**Bottom line:** the codebase is in good shape. The value-sign/perspective
machinery, the Gumbel completed-Q transform, sequential-halving selection, and
the soft-CE target plumbing are all correct and well-tested. The audit found
**one** real, production-affecting correctness gap worth fixing now (soft-CE
targets are not renormalized after the float16 replay round-trip), plus a set of
Elo bets that need arena validation before they touch the pinned production
config. It also dismissed two larger initially-flagged "critical/moderate"
findings as false alarms, with evidence, so they are not re-investigated.

## 1. Fix applied in this PR

### `soft_cross_entropy` renormalizes its target rows
`chess_anti_engine/train/losses.py`

Soft targets are stored as **float16** in the replay shards (`policy_target`,
`policy_soft_target`, `future_policy_target`, `sf_policy_target`,
`categorical_target` — see `replay/shard.py`). Round-tripping a wide
distribution through f16 leaves each row summing to `1 ± O(width·2⁻¹¹)` rather
than exactly 1. `soft_cross_entropy` is **linear** in the target, so that
residual row-sum scales the whole sample's loss and gradient. The docstring
already claimed the targets "must already be normalized," but nothing enforced
it: `align_policy_target` only renormalizes the full→compact projection path;
the production same-width path (`lc0_1858 → 1858`) and the value-space heads
(`categorical_t`) returned the drifted target untouched.

The fix renormalizes inside `soft_cross_entropy`:

```python
target_probs = target_probs / target_probs.sum(dim=-1, keepdim=True).clamp_min(1e-8)
```

- **Safe / zero-regression:** a no-op (within fp error) for already-normalized
  targets (`sf_wdl_probs`, the convex WDL blend), and `clamp_min` keeps
  all-zero (missing/masked) rows at 0 loss rather than NaN.
- **Impact:** removes a small, target-shape-dependent bias from every soft-CE
  head — largest on the main policy head (`w_policy = 1.0`). On peaked MCTS
  visit distributions the drift is small (~1e-5 relative); it is larger on the
  flatter `categorical_t` / smoothed `sf_policy_t` targets. This is a
  correctness/hygiene fix, not a large Elo lever on its own — but it also
  removes the latent landmine that any future label-smoothing or producer
  change could otherwise turn into a real bias (the exact concern flagged in
  the `align_policy_target` comment).

Tests added in `tests/test_losses.py`: scaling-invariance of the loss,
recovery of the float32 loss from a 1%-drifted / f16 round-tripped target, and
finite-zero handling of all-zero rows.

## 2. Verified correct (do not re-investigate)

- **Value sign / perspective** in both search paths. `_backprop` negates per
  ply; visited-child Q is consumed as `-child.W/N` (parent frame) everywhere
  (`gumbel.py`, `_mcts_tree.c`); returned root value is root-perspective.
- **WDL→Q** scalar (`(W−L)/(W+D+L)`, draw=0) is numerically identical in
  Python (`puct.py:_value_scalar_from_wdl_logits`) and C
  (`_mcts_tree.c:wdl_logits_to_q`).
- **Gumbel completed-Q transform** matches mctx: `mixed_value =
  (raw_value + ΣN·weighted_q)/(ΣN+1)`, min-max normalized completed-Q,
  `σ = c_scale·(c_visit + max_visit)`, improved policy
  `softmax(log_prior + σ(completedQ))`, deterministic non-root selection
  `argmax(prob − N/(1+ΣN))`.
- **Selfplay target POV**: per-ply outcome flip by `pov_color`, SF eval flipped
  back to record POV, t+2 future-policy indexing, no handicap leakage
  (targets use SF bestmove + full MultiPV softmax; the played handicapped move
  is stored separately). Covered by dedicated tests.
- **HL-Gauss** binning is symmetric about a draw; **Aurora** optimizer
  (Muon-style polar factor + leverage-uniform scaling) and the AdamW fallback;
  the `_SqrtReleaseLRScheduler` (WSD release) and linear warmup; the
  KataGo-style 50/50 uniform/priority replay sampling — all correct.

## 3. Dismissed false alarms (with evidence)

- **"Python and C Gumbel descent diverge at non-root nodes."** They do not. C's
  `tree_gumbel_collect_leaf` takes the `!any_visited` max-prior fast path only
  when *all* children are unvisited; in that case the Python improved-policy
  reduces to the same max-prior choice (completed-Q term is identically 0 →
  `argmax(softmax(log prior)) = argmax(prior)`). Once any child is visited both
  paths run the identical `tree_gumbel_select_child` / `_improved_policy_probs`
  scoring. Confirmed by reading `_mcts_tree.c:2564-2705` against
  `gumbel.py:284-342`.
- **"SF played-move regret is undercounted for moves outside the MultiPV set."**
  The curriculum move is *selected from* `cand_idxs`
  (`_choose_curriculum_opponent_move`) and diagnostics use the *same*
  `cand_idxs` (`_push_curriculum_opponent_move`), so the played move is never
  outside the set; when SF returns no PVs the target is a one-hot on SF's
  actual bestmove (`a_idx`), not an arbitrary move.

## 4. Elo bets — validation required (NOT changed here)

Per the repo protocol (audit-first, arena-validated, flags default off,
`pbt2_small.yaml` untouched until a bet clears its bar), these are left as
recommendations rather than production edits:

1. **Continuous target for the `value_categorical` head (highest-EV).** The
   32-bin HL-Gauss head trains on the ternary game outcome (`finalize.py:660`,
   `scalar_v ∈ {−1,0,+1}`), which is redundant with the `wdl` hard target and
   uses only ~2-4 of 32 bins. Feeding a continuous bootstrap value (e.g. the
   blended WDL expected score, or the SF-eval expected score) would make the
   distributional head a genuinely informative auxiliary signal. Flag-gate
   (`categorical_target_source: outcome|sf_eval|blended`, default `outcome`),
   sweep, kill if no arena gain over 2 perturbation intervals. The head is
   auxiliary (does not feed search) so the change cannot regress search.
2. **`gumbel_c_scale` sweep.** Default `0.1` is 10× below the mctx/paper
   reference (`1.0`); the value term in halving selection is correspondingly
   weaker. Already wired (`search.gumbel_c_scale`). Sweep {0.1, 0.3, 1.0} at
   the production 256-sim budget via `scripts/arena_standard.py --matched_sims`.

## 5. Minor items noted (not fixed)

- **Sequential-halving micro-overspend.** When `budget < len(rem)·rounds_left`,
  `vpa` floors to 1 and a round can spend ~1-2 sims beyond the budget
  (e.g. `budget=25, m=13 → 26`). Bounded by `len(rem) ≤ topk`; ~0 Elo. Fixing
  it correctly requires restructuring both the Python and C hot loops in
  lockstep, which is not justified for the gain.
- **`moves_left` normalized by `max_plies`** (`finalize.py:656`) compresses the
  target into a small fraction of [0,1]; raw plies (smooth-L1 handles scale)
  would be a cleaner target. `w_moves_left = 0.02`, so low priority.
- **`sf_multipv ≤ SF_MULTIPV_RAW_MAX` is only a warn-once.** Currently safe
  (40 ≤ 48), but raising `sf_multipv` past the cap would silently diverge
  stored sparse labels from live targets; a startup fail-fast would harden the
  offline-rebuild contract.
- **Illegal-move mass in soft targets** is amplified by the `-1e9` logit mask
  in `apply_policy_mask_to_logits`. Does not fire in production (MCTS/SF
  targets carry zero illegal mass), but if a future producer introduces it,
  zero the target on illegal moves before the soft CE.
