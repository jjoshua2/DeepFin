# D2 short-horizon metadata interface

This additive module validates metadata for the separately registered D2 question. It has no CLI, launches nothing, changes no model or bank and issues no acceptance. The existing HOLD ruler remains byte-for-byte V11; legacy, D1 and both historical K0 recovery routes are unchanged. Existing HOLD/SCORE/READ entry points do not automatically accept D2.

The complete GPU owner must be identical in learner and payload, closed PASS at 3600 seconds, with real actual admission SHA and exactly normalized SELF child. The new observer/source-review identity, study, registered design, selected run UUID, 512 updates / 16,384 views, source219, full architecture, fixed LR period4096, exact TRAIN192/N17568, frozen reference and whole-population/per-game coverage are checked. L0 and L1 resolve only to the fixed original D1 K0 corrective-v2 and K1 normal GPU receipt pairs. Their original K0/K1 labels, tags, sources, owners and proof limitations are retained in the return value; the caller's L0/L1 are display/comparison aliases. L0 stays a saved-only, current-CPU corrective endpoint with both failed historical owners preserved. It is not rebranded as a successful same-GPU proof or a permission to retry.

`role_authority(metadata, binding)` reads a distinct Root10 / independent12 role acceptance, source/protocol/closed CPU300 owner, and reviewed known-exposure registry. It returns the single SCREEN_C_A 14-field slice descriptor. It checks actual seven original/slice public book loads, strict full-history witnesses and actual count dictionaries. It does not open a book, roster or parent-map payload. Registry claims cover the declared controlled usage through the original 406-owner cutoff, not worldwide exposure.

`slice_projection(projection, entry, public_consumption)` is a separate in-owner pure predicate. After the actual owned consumer reads its authorized parent projection, it requires exact D2 projection9/game5/entry14 shapes, original ordinals80..159, local pair IDs0..79, complete parents and canonical order digest. It cannot qualify a role or turn old first80 metadata into a new slice. The producer's real full16/EPD loader witness must be authenticated first; the predicate does not infer histories from a hash.

## Actual sampler-prefix evidence

The observer's exact 27-field `draw_prefix_comparison` joins the fixed matching retained long delivery/boundary/journal with the complete actual short journal. It requires 512 ordered batches of32 /16,384 row IDs, all192-game membership, actual canonical prefix digests and exact row equality. Long streams are exactly three full stable readonly passes, each at most64 MiB, at most192 MiB additional long reads; one short pass and the total wrapper counter are within4 GiB. Pre/post/final stamps and full hashes must agree. The short whole raw digest also equals its canonical512-batch prefix digest because the unchanged public writer emits exactly canonical(batch)+newline.

This proves physical-row sampler prefix equality only. It does not prove mirror decisions, full stochastic-stream identity, arithmetic identity or equality with an unsaved historical step512 model. No prefix digest exists until a genuine owner produces it. The module never opens either real journal.
