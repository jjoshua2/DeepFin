# One later Ceres C3 CUDA probe — prepared, not launched

This prepares one C3-768-30-pre8-I8 direct ONNX Runtime session in a later GPU gap during CPU value rewriting. Active SoftSF training and arenas retain priority. Nothing is launched or queued; a busy existing GPU lease or another compute owner refuses. The exact outer argv template is `operator_command.json`; a future operator supplies one start+900-second deadline and records actual start/end/exit. The existing `bt4_direct_screen.run_owned_stage` supplies bounded owned-group cleanup and an inherited lease through child/timeout teardown. No new shared supervisor or active runtime change is introduced.

The saved policy and value banks join exactly on the same 128 original UINT8 `[64,137]` inputs, source/shard/row/game/ply identities and sampling weights. `references.npz` losslessly retains these bytes and their CPU policy/primary-value logits. `reference_assembly.json` binds all consumed original files and the original completed-bank receipts. Preparation read only these small saved artifacts, not the original corpus or histories, and ran no reference inference. It creates no native encoder/decoder dependency. Original float32 LC0 inputs, quantized training x and Ceres bytes are distinct representations; the probe uses only the saved original Ceres bytes.

The existing Python 3.10.12 / NumPy 1.26.2 / ORT 1.23.2 stack lists CUDAExecutionProvider. Default library resolution lacked cuDNN; an explicit child-only `LD_LIBRARY_PATH` resolves the already-installed cuDNN 9 and CUDA 12 libraries. `runtime_inspection.json` pins the executable, ORT/NumPy binaries, cuDNN libraries and CUDA-EP dependencies; no installation, global environment edit or CUDA session was performed. The collector checks loaded CUDA/ORT library identities again. Runtime options follow the [official CUDA provider contract](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html); provider availability alone is not GPU execution proof.

One session requests **policy and primary value together** for batches 1, 4, 16 and 32, in that fixed order, once over all 128 rows per size: 172 calls / 512 row-evaluations. Raw output precision remains float16. Policy is normalized only over the complete pinned legal roster; primary value is W/D/L logits from the current side to move, interpreted independently at temperature 1. No value2 blend or native-temperature package is selected.

Constructor and run fallback are disabled. The first B1 call is profiled: CUDA MatMul/Gemm-family events must exist, and any CPU event must be an explicitly allowed shape operator producing only small integer/bool outputs. CPU floating neural compute refuses. The same graph partition/session is retained for later batches, with providers checked again. This is explicit shape accounting, not a silent CPU fallback.

Prespecified raw-logit acceptance is `atol=0.02, rtol=0.002`; maximum legal-policy and WDL probability differences must each be at most 0.002, versus saved CPU B4 and GPU B1 references. Top-move changes must lie within a 0.004 reference-probability gap. Earlier eight-board CPU B1/B4 variability was 0.001953125 in raw logits and 0.0003513172 in legal probabilities: the proposed absolute allowances are approximately 10x and 5.7x those observations. The WDL bound is a prospective engineering tolerance; no WDL batch-variability bound was previously measured. CPU references are ORT 1.29, so this tests combined backend/version/batch agreement, not isolated same-version device error. Failure stops the attempt; no batch fallback, new rows, threshold adjustment or retry.

The outer bound is strictly 15 minutes including preflight, all hashes, startup, inference, profiling, readout and cleanup. The ORT arena is capped at 8 GiB; device-wide memory at 12 GiB and child RSS at 12 GiB are sampled every 5 seconds, with 16 GiB host available memory and 150 GiB local reserve required. The output guard samples 128 MiB aggregate logical bytes; a separate per-file ceiling is not an aggregate quota. Sampling can overshoot transiently. Both operator and child use CPU 0,1 at nice 19/ionice 3, with two numeric threads. The real operator's outer exit is required in addition to child/parent success receipts.

Session startup, each batch's first call and subsequent calls are reported separately. The first B1 call includes profiling. Host `session.run` times include synchronous transfers/results, but exclude normalization, guards and file writes. One ascending sweep on reused rows has cache/order effects; it is neither a production-labeler speed estimate nor a playing-strength result. Native repetition-edge and nondefault-Q input parity remain unresolved.

Five small CPU-only checks cover exact saved-reference comparison, material/NaN refusal, CUDA-versus-CPU event admission, and the actual nonexecuting CLI. The initial check/source/plan are preserved under `before_loaded_library_binding`; final checks followed the explicit loaded-binary binding addition. No ORT session, model inference, GPU work, process attachment, source scan or archive operation occurred.
